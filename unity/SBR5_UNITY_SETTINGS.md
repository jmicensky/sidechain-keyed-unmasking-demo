# Unity settings: one dynamics setting per mixer snapshot, all at SBR +5.0 dB

Generated by `demo_engine/analysis/write_unity_sbr5_handoff.py` (pipeline: `demo_engine/analysis/run_sbr5.sh`).
Supersedes the HI/NH choices in `SBR_SETTINGS_HANDOFF.md` for the test sequence; that document still explains the
metric, the LL Dynamics transfer and the calibration method in more depth.

## Decision (2026-10-15)

- **One SBR for every condition: +5.0 dB, tolerance +-0.10 dB** (Johnson & Healy 2024 SBR: speech-active
  RMS of processed Dialogue / RMS of the processed sum of Music, Background, Safety and Other; broadband, unweighted).
- **Reference scene: Construction** (judged the most realistic-sounding demo scene). The settings were searched so
  that Construction lands on target; the other two demo scenes are listed for reference only.
- **Dynamics only:** key gain and every makeup gain are 0 dB. In Group compression and Combined, Dialogue is itself
  compressed (ratio 2-4:1, 1.5-6 dB mean gain reduction) for intelligibility.
- Among settings within +-0.05 dB of the target, the search kept the one with the least gain reduction.

LL Dynamics column: offline emulation of the plugin (verified identical to `LLDynamicsProcessor.cpp`) with a
1024-sample (one block) Priority -> Sidechain lag, on the Construction stems at web-test levels.

## Effect chains

All LL Dynamics effects: Makeup 0 dB, Loudness Gate 0 (off), Priority Chan 1. Give each a Meter ID for logging.

- **Unmasked:** Dialogue = Priority (Mode 2). Music, Background Noise, Randomized FX = Sidechain (Mode 3, full band).
- **GroupCompress:** every group (Dialogue, Music, Background Noise, Randomized FX) = Compressor (Mode 1).
- **GroupCompressed>Unmasked:** Dialogue = Priority **then** Compressor (Priority first, so ducking is keyed on
  uncompressed Dialogue, as searched). Music, Background Noise, Randomized FX = Compressor **then** Sidechain.
- Randomized FX holds what the web test split into Safety and Other: use the **Safety** row for it.

## Getting exactly +5.0 +-0.1 dB in Unity

1. Enter the values above (plus each group's Delta) in the snapshot's LL Dynamics effects.
2. Measure SBR at the ear for that snapshot on the test material (the planned Hagerman & Olofsson tool).
3. If it is off, move only the trimmed thresholds (Sidechain threshold for Unmasked and GroupCompressed>Unmasked;
   the background-group Compressor thresholds together for GroupCompress) until it reads +5.0 +-0.1 dB.
4. Check the logged gain reduction against the targets above, so the processing character still matches.
5. Apply the equal-loudness correction afterwards; a whole-mix gain does not change SBR.

Why step 3 is needed: the coffee-shop material is not the Construction stems, and LL Dynamics' detector differs
from the web engine's, so the transferred values start close but are not guaranteed to land within 0.1 dB.

Listening examples (Construction, level-matched): `demo_engine/paper-audio/sbr5-construction/*.mp3`.
